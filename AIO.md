# AIO.md — оптимизация под ИИ: что публикует проект и по каким правилам

> Документ корпуса проекта, форма «правило → проверка → пример»: позже он станет навыком, и переписывать
> его не придётся.

**AIO (AI Optimization)** — это то же, что SEO, только читатель другой. Поисковик присылает человека на
страницу; модель приходит сама, читает и пересказывает. Разница в требованиях одна и решающая: человеку
нужна страница, модели — текст. Разметка страницы для неё наполовину мусор: меню, подвал, баннер
согласия, скрипты.

---

## Закон 1. Карта сайта для модели — `/llms.txt`

**Правило.** Проект отдаёт `llms.txt` в корне и на каждый язык (`/<язык>/llms.txt`). Строится он из
перечня публичных поверхностей `lib/aio/surfaces.ts` — того же, из которого берутся markdown-версии.

**Форма — из первоисточника https://llmstxt.org, и она строгая:**

1. `# Заголовок` — единственный обязательный элемент;
2. `> цитата` с кратким описанием, несущим всё нужное для понимания остального;
3. необязательные абзацы **без заголовков**;
4. необязательные разделы `## Название` со списками ссылок `- [имя](адрес): пояснение`.

Раздел `## Optional` — служебное имя из спецификации: ссылки, которые агент вправе пропустить, когда
контекст надо сократить. У нас туда уходят правовые страницы. Имя раздела не переводится — по нему агент
и узнаёт, что содержимое второстепенно.

**Назначение формата — вывод модели (inference), а не обучение.** Так сказано в спецификации.

**Проверка.** `npm run check:aio` + живой прогон: каждая ссылка карты отвечает 200.

## Закон 2. `llms-full.txt` — практика, а не стандарт

**Правило.** Мы отдаём `llms-full.txt` (полные тексты одним документом) и НИГДЕ не называем его
стандартом: в спецификации llmstxt.org такого файла нет. Сам файл говорит о своём происхождении первой
строкой.

**Почему это важнее, чем кажется.** Выдать практику сообщества за стандарт — та же ошибка, из-за которой
в проекте появилось правило «факт о чужом продукте только из первоисточника». Один раз назвав так, мы
понесём это в документацию, в маркетинг и в ответы клиентам.

**Проверка.** `npm run check:aio` падает, если слово «стандарт» окажется рядом с `llms-full.txt`.

## Закон 3. У каждой публичной страницы есть markdown-версия

**Правило.** Адрес — `<адрес страницы>/index.md`. Для страниц он строится `mdUrlFor(lang, subPath)`.
Форма из спецификации: markdown рядом со страницей, для адреса-каталога — `index.md`.

**Языковой сегмент в этом адресе есть ВСЕГДА**, даже в одноязычном режиме. Причина не в красоте:
`proxy.ts` не обрабатывает пути с точкой (его матчер исключает `.*\..*`), поэтому переписать `/index.md`
в `/en/index.md` некому — маршрут лежит под `app/[lang]/…`, и адрес обязан вести туда напрямую. Этот
дефект уже был: карта печатала `/index.md`, и агент получал 404 на первой же ссылке.

**Пример.** Новый маршрут — три строки:

```ts
import { markdownRoute } from "@/lib/aio/md-route"
const md = markdownRoute("/blog")

export const dynamic = "force-static"
export const dynamicParams = false
export const generateStaticParams = md.generateStaticParams
export const GET = md.GET
```

Значения сегмента объявляются литералами: Next разбирает их статически и переэкспорт из объекта не
принимает («needs to be a static boolean»).

**Проверка.** `npm run check:aio`: публичная страница без соседней папки `index.md` не проходит.

## Закон 4. Источник текста — один

**Правило.** Markdown собирается из ТЕХ ЖЕ блоков, что и страница (`lib/aio/blocks-to-markdown.ts`).
Отдельный «файл для ИИ», написанный руками, запрещён.

**Почему.** Копия расходится с оригиналом на первой правке, и никто этого не заметит: markdown-версию в
браузере не открывают. Сегодня расхождение — это модель, пересказывающая устаревшую цену.

---

## Закон 5. В карту попадает только публичное

**Правило.** Страницы под `(protectedLayer)` не имеют markdown-версий и в карту не входят.

**Почему.** Карта для модели — приглашение прочитать. Закрытый адрес в ней не «утечка данных» сам по
себе, но приглашение агенту постучаться туда, куда его не звали.

**Проверка.** `npm run check:aio`.

---

## Закон 6. Каталог называется, товары — нет

**Правило.** `llms.txt` перечисляет разделы, а не строки базы. У каждого товара есть своя
markdown-версия по своему адресу, и приходят на неё по ссылке из карты сайта.

**Почему.** Множество товаров растёт в рантайме и умножается на языки. Файл, выросший до предела,
перестаёт работать целиком — тот же урок, что с `sitemap.xml` и его 50 000 адресами.

---

## Что делает автор поста

Ничего дополнительного. Пост появляется в карте и получает markdown-версию сам, потому что и то и другое
берётся из перечня поверхностей. Единственная обязанность — завести markdown-маршрут при создании НОВОГО
раздела; `npm run check:aio` об этом напомнит отказом.

| Команда | Что ловит |
|---|---|
| `npm run check:aio` | страница без markdown-версии; карта-заготовка; закрытый адрес в публикации; `llms-full.txt`, названный стандартом |
| живой прогон | каждая ссылка обеих карт отвечает 200 |

**🔒 Все три гейта (`check:seo`, `check:aio`, `check:pwa`) встроены в `prebuild`.** Это не украшение:
проверка, которую надо помнить запускать, не запускается. Теперь сборка со страницей без markdown-версии,
без `alternates` или с воркером, отдающим страницы из кеша, **не собирается вовсе** — а значит и не
разворачивается.
