# SEO.md — как поисковая оптимизация устроена в этом проекте

> Документ корпуса проекта. Написан в форме «правило → проверка → пример», потому что позже он станет
> навыком: правило переезжает в тело навыка, проверка — в его гейт, пример — в его образец.

Читать перед любой работой, которая создаёт публичную страницу, меняет её адрес или трогает метаданные.

---

## Закон 1. Публичная страница отдаётся готовым HTML

**Правило.** Каждая публичная страница статическая или ISR. Динамика на публичной поверхности
запрещена: `force-dynamic`, `headers()`, `cookies()` и клиентский компонент, владеющий маршрутом, — всё
это выводит страницу из-под предрендера. Корневой `force-dynamic` делает динамическим ВСЁ поддерево.

**Почему.** Готовый HTML читается с выключенным JavaScript и отдаётся за одинаковую цену на сотне визитов
и на сотне тысяч. Это и есть та часть, которую проекты теряют незаметно: страницы становятся
пересчитываемыми на каждый заход, растёт время ответа, вместе с ним растёт счёт за сервер.

**Проверка.** `npm run build` — в выводе у публичных маршрутов стоит `○` (static) или `ISR`, а не `ƒ`.

## Закон 2. Каждая страница объявляет СЕБЯ оригиналом

**Правило.** У каждой публичной страницы своя `generateMetadata`, и в ней —
`alternates: buildAlternates(lang, subPath)`. Ни одна страница не полагается на метаданные макета.

**Почему.** Метаданные в Next наследуются. Пока у главной не было своих альтернатив, она брала
канонический адрес у макета — а он один на всё дерево и равен корню сайта. `/ru` дословно объявлял себя
копией `/`: «индексируй не меня». Ошибочный канонический адрес хуже отсутствующего — отсутствие
трактуется как «страница сама себе оригинал», чужой адрес читается как просьба её не индексировать.

**Пример.**

```ts
export async function generateMetadata(
  { params }: { params: Promise<{ lang: string }> },
): Promise<Metadata> {
  const { lang } = await params
  return {
    title: ui(lang).metaTitle,
    description: ui(lang).metaDescription,
    alternates: buildAlternates(lang, "/blog"),   // главная — пустая строка
  }
}
```

**Проверка.** `npm run check:seo` — падает на странице без `generateMetadata` или без `alternates`.

## Закон 3. Переводы называют друг друга, иначе они копии

**Правило.** При двух и более языках у каждой страницы есть `hreflang` на все языки плюс `x-default`.
Строит его тот же `buildAlternates` — отдельного действия не требуется.

**Почему.** Перевод, который не назвал своих братьев, не читается как перевод — он читается как копия. А
набор одинаковых по смыслу адресов, ни один из которых не назвал себя оригиналом, поисковик относит к
дорвеям. Цена ошибки — не позиция ниже, а отсутствие целых языков в выдаче при полностью исправном
на вид сайте.

**Проверка.** В разметке страницы: `<link rel="alternate" hrefLang="…">` на каждый язык и `x-default`.
(Next печатает атрибут как `hrefLang` — это нормальная сериализация React, HTML разбирает имена атрибутов
без учёта регистра.)

## Закон 4. Один язык — значит в адресах языка нет

**Правило.** Все адреса строятся `urlFor(lang, subPath)` из `lib/seo/alternates.ts` — и в
метаданных, и в картах сайта, и везде, где мы печатаем ссылку на свою страницу. Руками адрес не
склеивается никогда.

**Почему.** Одноязычный режим включается сам при одном значении в `NEXT_PUBLIC_SUPPORTED_LANGUAGES`, и
`proxy.ts` убирает языковой сегмент из всех публичных адресов: `/en/products` отвечает 301, страница
живёт на `/products`. Ручная склейка `${site}/${lang}${путь}` — второй источник правды об адресах; он
расходится с первым ровно в этом режиме, и тогда канонический адрес и каждая строка карты сайта ведут на
редирект.

**Проверка.** `npm run check:seo` ловит ручную склейку; в одноязычной сборке `sitemap.xml` не содержит ни
одного языкового сегмента.

---

## Закон 5. Мету собирает один механизм

**Правило.** Заголовок, описание, ключевые слова, OpenGraph, карточка X/Twitter, robots, подтверждения
поисковиков — через `constructMetadata` (`lib/construct-metadata.ts`). Руками объект метаданных не
пишется.

**Почему.** Написанный руками набор покрывает поля, о которых вспомнили. Через полгода половина страниц
отдаёт в соцсети описание сайта вместо описания страницы.

**Тонкость.** `constructMetadata` без `pathname` НЕ отдаёт канонический адрес — намеренно, см. закон 2.
Канонический адрес приходит из `buildAlternates`, и это единственный его источник.

---

## Закон 6. Структурированные данные

**Правило.** Сайт и организация объявляются в макете; страница объявляет то, чем является: товар —
`Product` + `Offer`, статья — `NewsArticle`/`BlogPosting`/`TechArticle` с автором-личностью и издателем,
любая вложенная страница — `BreadcrumbList`, блок вопросов — `FAQPage`. Сборщики — `lib/jsonld.ts`.

**Почему.** Из этого вырастают расширенные результаты выдачи. Написанный руками JSON-LD расходится с
содержимым страницы при первой же правке текста.

## Закон 7. Карты сайта и robots

**Правило.** Множество конечное и авторское — в `app/sitemap.ts`. Множество, растущее в рантайме
(товары), — в `app/products/sitemap.ts`, разбитой на порции. `robots.txt` собирается из настроек и
перечисляет все карты.

**Почему.** Предел одного файла — 50 000 адресов, и при превышении поисковик отбрасывает файл ЦЕЛИКОМ,
вместе со страницами. Адресов у нас товары × языки, и этот предел достигается быстрее, чем кажется.

**🔒 Раздел, которого нет ни в одной карте, не существует для поиска.** Закон 7 говорил, КУДА класть
множество, и молчал о том, что положить обязано КАЖДОЕ. Разница стоила блога: `/ru/blog` отдавал 200,
оба поста были написаны и переведены, `check:seo` был зелёным — а карта знала только главную и товары.
Проверки законов 2-5 стерегут качество сигналов у страницы, которая до карты дошла, и ничего не говорят
о странице, которой в карте нет вовсе; ненайденная страница не выигрывает от идеального `hreflang`.

Посты в карту попадают сами — список берётся из `_list.generated.ts`, того же файла, что питает
страницу блога. Новый РАЗДЕЛ — одна строка в `app/sitemap.ts` (или своя карта, если множество растёт
в рантайме). Страницы за авторизацией в карту не попадают никогда: их не существует на сборке, а
поисковик получил бы форму входа.

**Проверка.** `npm run check:seo` отказывает разделу со страницей, не представленному ни в одной карте.
Разделом считается папка с `page.tsx` — соседние `llms.txt/` и `manifest.webmanifest/` это машинные
маршруты, им в карте страниц делать нечего.

---

## Закон 8. Ссылки внутри материалов

**Правило.** Внешняя ссылка — всегда с полным адресом, открывается в новой вкладке, чужой домен получает
`nofollow`. Внутренняя — только корневая формы `[%SITE%](/ru)`, и она обязательна в каждой языковой
ячейке поста.

**Проверка.** `npm run check:content`.

---

## Что проверяется машиной — сводка

| Команда | Что ловит |
|---|---|
| `npm run check:seo` | страница без `generateMetadata`; страница без `alternates`; ручная склейка адреса с языком; канонический адрес в макете; **раздел, не представленный ни в одной карте сайта** |
| `npm run check:content` | нарушения закона 8, отсутствующие медиафайлы, непереведённый пост |
| `npm run check:i18n` | пропавшие строки интерфейса |
| `npm run build` | публичные маршруты остались статикой/ISR |

**Гейт важнее аудита.** Разовая проверка живёт до конца сессии, гейт — сколько живёт проект.
