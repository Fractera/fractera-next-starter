# m13 — Перенос данных и ключей

**Стоит последним и по ОТДЕЛЬНОМУ доступу владельца.** До этого шага цена ошибки почти нулевая: ломается
пустая копия, а не живые записи людей.

**Что переносим.** Старую базу PostgreSQL — сферы, сегменты, замеры, привычки, отметки, связи коуч ↔
клиент, приглашения, подписки — и файлы из UploadThing.

**Что НЕ переносим.** Карточки пользователей целиком: имя, почта, аватар живут в слое авторизации
платформы. Из `User` едут только подписка и признак коуча.

**Ключи облачных сервисов — развилка: агент предлагает, владелец решает.**
1. Владелец заводит ключи на странице панели «Переменные окружения» и повторяет перенос переменных на
   свою машину кнопкой «копировать → вставить».
2. Либо не держит эти ключи на сервере вовсе: ставит их только локально и говорит «ключи добавлены» —
   шагов меньше, секреты ближе к нему.

**Сшивка личностей.** У каждой старой записи есть `clerkUserId`. Нужна таблица соответствия
`clerkUserId → user_id` платформы: строится один раз, до переноса, и проверяется на десяти записях
прежде, чем поедет остальное.

**Доказательство.** Число строк по каждой таблице совпадает со старой базой; десять случайных записей
сверяются полями; клиент входит и видит свою историю замеров.
