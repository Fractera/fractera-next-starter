# 541 — страница «Секции»: типизация каталога, превью и номера

**Заведён 2026-08-22** по замыслу владельца. Записан ПОСЛЕ начала работы — это нарушение порядка, и
оно названо здесь честно: план полагается заводить до кода, а не восстанавливать задним числом.

## Зачем

В карте дизайна панели стояла строка «Секции» с меткой «скоро» — обещание без страницы. Владелец
открыл эту работу: типизировать блоки по назначению, снабдить описаниями, дать поверхность, где
секции видно.

Побочная цель, названная владельцем: **навык становится лучше** — агент выбирает не по имени вида, а
по назначению: «нужен раздел про шаги» → тип «как это работает» → `flow`.

## Решения владельца, дословно

- «тексты должны быть только на английском языке то есть секции не переводим»;
- левая колонка — **аккордеон**, открыт один тип; внутри под-аккордеон видов; внутри вида — «настройка
  для выбранного заголовка, то что должен читать искусственный интеллект»;
- вверху **оранжевый контейнер с цветком** «как добавить новую секцию»: её пишет агент-программист на
  локальной машине, потом вернуться и посмотреть, что получилось;
- у каждой секции **числовой идентификатор** вида `0001` — «чтобы не было опечаток»;
- файл-перечисление: идентификатор, тип, имя, описание — «именно этот объект должен пожрать
  искусственный интеллект»; плюс **на какой странице секция стоит и какой по порядку**;
- корень остаётся у стандартной архитектуры (из соседнего разговора, к этому шагу не относится).

## Что построено

**Одиннадцать типов** — `sections/taxonomy.json`, чистые данные: десять частей посадочной страницы от
владельца плюс «материал страницы», чтобы ни один вид не остался без дома. Там же номера видов и
`shape` — как панель рисует превью.

**`sections/SECTIONS.json`** — порождается тем же скриптом, что и `BLOCKS.md`; свежесть обоих стережёт
`check:blocks-map` в `prebuild` (негативный контроль пройден: порченый файл роняет гейт). В каждой
записи: номер, вид, тип, форма, поля, описание из карточки и **где вид стоит** — страница, порядковый
номер на ней, сколько раз. Применение СЧИТАЕТСЯ обходом `en.ts` публичных страниц, а не ведётся руками.

**Страница панели** `/<lang>/design-sections`: двухуровневый аккордеон на `<details name>` — без единой
строки JS, исключительность даёт браузер, открытое состояние выводится из адреса (`?kind=`). Справа
превью схемой (75%), над ним оговорка, что на сайте вид другой. Оранжевый блок о новой секции — вверху.

**Каталог читается из слота** (`APP_DIR`), копии в панели нет: панель и приложение — разные
приложения, и копия разошлась бы с реестром на первом же новом виде.

**Слова страницы вынуты из корпуса переводов** в `_components/ui.ts`: страница английская по решению
владельца, а русская ячейка с английским текстом обманывала бы проверку полноты.

## Что осталось

🔥 **Описания видов — два из двадцати девяти.** Это и есть то, «что должен читать искусственный
интеллект»: сегодня в аккордеоне у двадцати семи видов честная строка «заметок пока нет». Карточка
рождается, когда о виде что-то узнали, — но у одиннадцати лендинговых видов знание уже есть, его просто
никто не записал.

**Порядок написания предложен такой:** сначала одиннадцать лендинговых (`hero`, `heroSplit`, `cards`,
`badges`, `flow`, `problemSolution`, `noBill`, `founder`, `metrics`, `languageMarquee`,
`projectTypeMarquee`) — их выбирает агент, когда строит страницу. Материал страницы (18 видов) — потом
и по поводу.

**Три типа не закрывает ни один вид:** `product-demo`, `use-cases`, `showcase`. Страница показывает их
пустыми — это очередь работ, а не дефект.

## Чего в этом шаге НЕ делали

- Не переводили страницу на 82 языка: решение владельца — каталог секций не переводится.
- Не строили секции под пустые типы: каждая — отдельная работа с рендерером, образцом и гейтами.
- Не трогали галерею приложения `/blocks`: она остаётся единственным местом, где виды рисуются
  настоящим кодом и с оформлением владельца.
