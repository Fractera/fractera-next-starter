# chartRadar — лепестковая: профиль по нескольким мерам

Фигура по кругу: у каждой меры своя ось, два ряда наложены. Легенда снизу, подвал под ней.

## 🔒 ОТРИЦАТЕЛЬНЫЕ ОТСТУПЫ ПЕРЕНЕСЕНЫ КАК ЕСТЬ

`top: -40`, `bottom: -10` — не опечатка источника. Они прижимают фигуру к легенде и убирают
пустую полосу, которую диаграмма оставляет под несуществующее заглавие. «Поправленные» на ноль
отступы дают карточку с дырой сверху.

## 🔒 ПЕРВЫЙ РЯД ПОЛУПРОЗРАЧЕН, ВТОРОЙ НЕТ

Две сплошные заливки друг поверх друга скрывают нижнюю целиком. На лепестковой это не «наложение
цветов», а потеря ряда.

## Когда НЕ брать

- Мер больше шести — подписи по кругу перестают читаться.
- Нужны точные величины: по кругу их не считывают, для этого таблица или столбцы.
- Мера одна — это любой из линейных видов.

## Откуда взялась форма

Перенесена с `https://ui.shadcn.com/charts/bar#charts` 2026-08-30 по прямому указанию владельца:
«мы создадим в нём по одной диаграмме, и я тебе пришлю их исходный код». Исходник лежит в учёте
шага 58, папка `new-steps/58/sources/`.

## 🔒 ЦВЕТ РЯДА — РОЛЬ ПАЛИТРЫ, А НЕ ЗНАЧЕНИЕ В КОДЕ

Решение владельца 2026-08-30, дословно: «цвета диаграмм — часть палитры дизайна». Ряды берут
`var(--chart-1)` … `var(--chart-5)`; умолчание живёт в теме, человек правит их на
`/{lang}/architect/design?section=colors`, и правка видна без пересборки. Записать цвет прямо в
блок нельзя: он пережил бы смену палитры и остался единственным пятном старого оформления.

## 🔒 ВИД СОСТОИТ ИЗ ДВУХ ПОЛОВИН

Ни один файл под `sections/` не бывает клиентским. Рендерер остаётся серверным и переводит поля
блока в пропсы островка `components/charts/chart-radar.client.tsx`, где и живёт движение.

## 🔒 ДАННЫЕ НЕОБЯЗАТЕЛЬНЫ

Не прислали своих — рисуется `MONTHS_6` из `components/charts/sample-data.ts`, тот самый массив
из исходника владельца. Пустая карточка на витрине читается как поломка вида.
